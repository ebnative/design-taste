## Component adoption record

For a chosen item, record: card ID and exact component URL, repository revision or registry version, license/terms scope, dependencies, required semantic tokens, props/states, interaction trigger, keyboard/touch behavior, reduced-motion fallback, content constraints and actual verification views. This goes into the private job record and production repository, not client data in the atlas.

Prefer one behavior system per coherent interface unless the existing project needs otherwise. Compare the actual dependency/interaction contract before mixing libraries. Replace demo copy and imagery with authorized project content; a component license does not license every photograph, trademark or recording in its demo.

## From reference to a design decision

Capture a specific section or state, describe its communication role, then propose how to translate it into the selected direction. Do not import the reference's palette/type/motion personality as a new direction. When the translation requires a direction change, append the PROCESS.md proposal and let the brain resolve it.

A gallery screenshot is internal inspiration. A licensed code copy is an inert input. Neither is a finished working page. Recheck actual behavior at 390 px and 1280 px, keyboard/focus/labels/contrast and relevant states. An accessibility marketing claim is not our test result.
