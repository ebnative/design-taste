# Evidence-based style learning

Read at the beginning of a task and before persisting learning.

## What to record

- Explicit lasting preferences (for example, "I always prefer geometric sans type") can enter the general profile immediately.
- Project-specific commands (for example, "make this poster red") belong to that project's context, not the general profile.
- Approval of a complete design is evidence for that design, not proof the user prefers every detail. Record the approved artifact and only promote specific observations to general preferences when supported by explicit feedback or repeated choices across independent projects.
- A correction without clear scope is a candidate with its source and limited applicability; it must not become a hard global rule. Silence, downloads, successful exports and agent self-evaluation are not user approval.

For each learned preference include: preference, scope (general/project/candidate), evidence (dated quote or accurately paraphrased feedback plus artifact path when relevant), confidence (explicit/repeated/tentative), and date. Do not invent quotes or approval. Preserve reference file paths rather than copying entire source documents into memory.

Resolve the private root using [private memory](../../../workflows/private-memory.md) and read the current profile before patching it. Merge entries; avoid duplicates. A newer explicit correction supersedes the conflicting preference with the reason recorded. Evidence and user paths stay outside the shareable repo. Preserve existing installed style/memory files during migration; do not automatically copy them to the atlas.

## Improve execution separately

After an observed failure and successful repair, add a concise, reproducible entry to `references/verified-recipes.md`: task, Illustrator version, method, actual verification, limitation and date. A script that has merely been written is not a verified recipe. Generalize only the demonstrated invariant; keep an isolated project's choices out of universal rules.

Update SKILL.md or helpers only when evidence warrants a workflow/code correction. Validate modified helpers and the skill manifest. Do not expand app permissions, install plugins, or change unrelated skills/configuration as part of learning.

Tell the user briefly what lasting preference was learned when a meaningful update occurs. Provide the profile if they ask to inspect it; remove or revise preferences on request. Learning occurs within active skill use, not on a background timer.
