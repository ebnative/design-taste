v0 skeleton; no route or recipe is verified by these instructions.

Read the [motion-branding workflow](../../workflows/motion-branding.md) and [video-editing workflow](../../workflows/video-editing.md) as needed.

## Translation rules
For every job resolve this motion-scope question: is the output (a) video embedded in a page, (b) on-page interaction animation, or (c) a standalone film/launch video? Ask only if the brief has not answered it; mixed scope needs separate deliverables.
Translate MOTION.md duration, easing, rhythm, choreography, holds and picture-sound tokens into storyboard/specification sections. The brain owns direction tokens; the discipline may add storyboard and specs only. TR-001 suggests short durations/no overshoot; TR-002 suggests longer ease-out/overlap only under the chosen direction. Record any requested direction change in PROCESS.md.

## Outputs
For embedded video, deliver the rendered film and page integration requirements; for interaction animation, deliver working code/interactive HTML and exercised states; for standalone film, deliver the render and its editable source. Native AEP/PRPROJ, a code project, interactive HTML and an MP4 are distinct outputs. Preserve the required native/code master, frame rate, dimensions, duration, sound sources and EXPORTS.md evidence. Inspect actual playback and meaningful frames; a single screenshot cannot verify motion.

## Discipline critique checklist
Check timing/easing against tokens, reading holds, visual rhythm, transitions, picture-sound synchronization, captions and reduced-motion behavior for interfaces. Inspect full playback, boundaries, missing media and final duration. Keep coherence with graphic/web work distinct from medium-specific findings.

## Production handoff
Request video.code-render (candidate: Remotion), web.interaction-animation (candidates: GSAP/Motion), video.native-ae or video.highlight-reel (candidate: Adobe Quick Cut if verified). Resolve operations through adapters/routes.json; the brain verifies live availability as well as recorded evidence. Separate page video delivery from interaction code and standalone renders. Render project dependencies belong in separate repositories. Unverified routes may be planned, never promised.
