# Graphic reference production and comparison

Use this workflow when a user selects an archive card, says “use this style”, or requests a reference-driven graphic. Read the actual private reference media, the selected entry in archive/graphic-studies.json, and the job brief. Search retrieves candidates; the selected image and brief govern production.

Resolve the private root from the current session or DESIGN_TASTE_PRIVATE_ROOT. An installed skill may also carry a local style/archive-location.json with private_root and graphic_catalog; it is operational host configuration and stays outside the shared repository. An absent configuration is not evidence of an empty archive. Reuse an existing confirmed archive before creating another root.

## Selection and direction

Resolve the card ID and exact image/frame/subdirection. A montage is not one style. GD-004 and GD-010 are one Physalia project with complementary evidence. GD-006 is a tactile poster canvas, not proof of an archive application's behavior. Preserve these distinctions.

Freeze the exact copy, language, audience, dimensions, required smallest view and intended use. If a real project is not yet specified, make an explicitly provisional studio study; do not invent personal/client facts or alter a live portfolio. Build three distinct thumbnails when selecting a new direction; once the user has selected a direction, refine it without repeatedly reopening selection.

The brain writes the selected reference ID/frame, transferable principles, original changes and authored tokens in DESIGN.md. Record which properties matter: composition, visual hierarchy, typography, color roles, material detail, negative space, conceptual fit and series coherence. Source observations, measured values, estimates and authored proposals stay labeled separately.

## Private graphic library

Keep source screenshots, photos, posters, video frames and failed-download receipts outside the repository. The canonical public study index contains observations and authored recipes only. Each private study has source media/receipts, ANALYSIS.md, RECIPE.md, tokens.json, a selection prompt and links to trials. Store an image inventory with file hashes and provenance; a video poster is not a downloaded video. Keep source identity and trial identity visually distinct.

Generate the offline preview library with scripts/build_graphic_archive.py in the repository, or bundle/tools/build_graphic_archive.py in a relocated skill package. The library combines text search, style/use filters, local favorites and detail views; actual jobs add reference/trial comparisons at comparisons/index.html. Its prompts are handoffs to an agent; the HTML does not call a model or execute a production job. Source assets are private study material, never included in a public export. Retain existing web collections and link the two libraries without rewriting their specimens.

## Reuse executed archive studies

Before starting another trial, inspect the confirmed private library's `production-ledger.json` when present. Resolve the selected reference ID to its existing job manifest, inspect the best actual export and read its critique, changed variables and editable scope. A ledger entry alone is not evidence that a file exists or a method succeeded. Retain previous attempts and use the strongest demonstrated operation as the starting point for the new brief; do not repeat a rejected material approach without a reason. Keep still-mode comparability separate from unavailable source animation, native production and human acceptance. Source recipes remain hypotheses where their operations were not executed; original adaptation evidence belongs to the separate job record.

## Produce, compare, revise

1. Read the reference pixels and recipe. Acquire required authorized assets or identify the concrete missing asset. Select a currently available production route; preserve the Photoshop/Adobe deferral. Original vector studies may use an existing code-render route as their own medium, never as Photoshop simulation or native-delivery evidence.
2. Produce an editable trial and full-size/reduced flat exports. For photo-led work, use an owned or cleared photograph; an authored vector plant is an illustration and cannot satisfy photographic material quality. For motion, render a real sequence and inspect playback, pause and reduced-motion behavior.
3. Compare the actual reference and trial side by side at equal artwork height, equal viewing scale and the same flat/mockup conditions where available. Inspect a full-size crop for edges/material and a reduced view for hierarchy. Disclose when a reference is itself only a screenshot or a four-up board.
4. For every criterion record: reference observation, trial observation, remaining gap, changed variable and next correction. Use better / comparable / weaker / unverified with a reason; avoid numerical aesthetic precision and do not average a serious readability, rights or editability failure into success.
5. Save each trial, export and critique under a new revision. Change the highest-impact gap first, then re-render and compare. Keep the best candidate and rejected candidates; do not substitute a written plan for the next actual authorized revision.
6. Continue while there is a concrete correction and a viable local route. A default checkpoint after three revisions is a progress/reassessment point, not automatic completion. If it is still weaker, change the approach and continue. After two materially different approaches make no visible progress on the same gap, record a plateau with paired evidence, preserve the best result and explain the required asset, tool or human decision. Never manufacture an endless loop or silently declare parity to stop.

“As good as the reference” is a brief-specific visual judgment. Model-assessed comparability requires actual paired inspection and no unresolved material gap in the agreed criteria. User acceptance remains pending until explicit feedback. Never claim human approval, professional equivalence or full source fidelity from a successful render or passing software tests. A plateau is incomplete work, not a passed design.

## Trial record and handoff

Use the job's BRIEF.md / DESIGN.md / PROCESS.md / EXPORTS.md. Keep a trial manifest with reference_id, reference_image, target_use, revision, editable_source, flat_export, reduced_export, changed_variables, criterion_findings, verdict, next_action and human_acceptance. Distinguish concept selection from revision. Link trials into the private comparison viewer and retain their concrete gap notes. New trials do not promote the third-party reference to executed-verified or an original result to an approved showroom card.

Read authored recipes as hypotheses until their specific operation and outputs have executed evidence. Extract a reusable production recipe only from a completed, inspected operation, preserving remaining visual and tooling limits. Public recipe evidence must omit personal data and private media.
